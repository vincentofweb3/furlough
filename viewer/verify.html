Three cuts, no unlock transactions

The product claim, as recorded on chain. "Lifted" means the deadline passed and the allowance returned by itself.

ui-check-1 ran in a deliberately short 180s window so the board could be captured in both states; the 900s default was restored in a separate policy transaction. No method exists that lifts a cut early. The only write after a cut is reap_expired, which records lifted_at for the public log and changes no allowance.

Read it yourself

The CLI in the repository reads the same state as this page. It needs no wallet for status.

git clone https://github.com/vincentofweb3/furlough
cd furlough
python3.12 scripts/live_check.py status

Filing a case is permissionless; any testnet key works and Studionet charges no gas. See docs/DEPLOY.md for the full smoke test.

What is not shown

No live value loop

The deployed contract has deposited = 0. Custody and draw semantics are covered by hermetic tests, not by a live funded agent. A live demo needs a funded key and a real agent journal.

No real inter-model agreement proof

The consensus path was exercised live; the hermetic gate uses a deterministic test model. Proving two real models agree on borderline evidence needs a production network.

Not audited

This is a testnet contribution. Do not use it with real value.

Journal trust

Validators fetch the journal independently, but nothing proves the agent authored it. Signed digests are the documented next step.
